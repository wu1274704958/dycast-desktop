# Recoil Live Gameplay 联调桥接

此独立进程接收 Dycast Desktop 的 WebSocket 转发，转换为引擎现有的 Windows 命名管道协议。不会修改游戏业务逻辑。

1. 安装 Node.js，在本目录执行 `npm install`。
2. 启动游戏，等待场景初始化完成。发现文件位于游戏 write-dir 的 `live/live-gameplay.json`。
3. 执行 `npm start -- "D:\code\RecoilEngine\build-test-runtime\live\live-gameplay.json"`。也可设置环境变量 `RECOIL_LIVE_GAMEPLAY_DISCOVERY`。
4. 使用本仓库修改后的 Dycast Desktop 连接抖音直播间，将 WS 地址设为 `ws://127.0.0.1:8765` 并点击「转发」，在过滤器中启用需要的消息类型。

可通过环境变量 `RECOIL_DYCAST_PORT` 修改监听端口。服务仅监听本机。引擎重启后自动重新读取发现文件并连接；断线和拥塞期间消息直接丢弃，不做重放，避免旧命令延迟执行。用户 ID 加 `douyin:` 前缀，防止与其他平台用户冲突。

支持聊天、进场、点赞、关注、分享、礼物和直播开始/结束。点赞每条消息对应游戏的一次点赞事件，不按消息里可能包含的点赞数量放大奖励。抖音没有 B 站舰长等级的对应语义，不伪造 `guard_buy`；主播不传来的粉丝牌、管理员等字段不填。

礼物按抖音的连击组 ID 和累计数量计算增量，同组重复帧和结束帧不重复发放；没有组 ID 的礼物只有在数量为 1 且有消息 ID 时才会转发。连击去重状态只保留在当前进程，最多 50000 组，进程重启后不会恢复，不能保证跨重启的恰好一次投递。

游戏 `price` 是礼物单价（分）。默认按 1 抖币 = 10 分换算，启动前可设置 `RECOIL_DOUYIN_FEN_PER_DIAMOND` 为其他非负整数。抖音消息中的价格、数量、社交 action 及连击语义尚未通过真实直播数据验证，实际应用前需检查桥接日志并核对真实礼物；礼物名称还需与游戏配置匹配。

控制台日志记录发现文件、管道连接/断开、房间信息、转发计数、礼物名称/数量/单价和转换错误；不会记录完整弹幕或凭证。转发成功只表示已写入本地管道，游戏协议没有业务确认，不能证明游戏已处理。桥接程序与其他命名管道客户端不能同时连接同一个游戏实例。
